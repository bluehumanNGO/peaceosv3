# Example VEP packages

Generated by `src/generate.ts` (`pnpm run generate`). Regenerating overwrites
everything in `packages/`, `keys/*.pub`, and `transparency/`.

- `keys/field-01.pub`, `keys/org-2026.pub` — the demo identities' public keys.
  Private keys (`*.key`) are regenerated locally and are not committed (see
  root `.gitignore`) — no real secret is at stake, but the project's own rule
  is "no secrets in the repo," so we don't make an exception for demo ones.
- `transparency/keys/org-recolectora/org-2026.pub` — a stand-in for a local
  checkout of the separate, public `peaceos-transparency` repo (see
  `AGENTS.md`). Pass `--transparency examples/transparency` to `check`.
- `packages/valid.vep/` — a package built with real network OpenTimestamps
  calendar submission (falls back to an offline, never-submitted pending
  proof if the network is unavailable when `generate.ts` runs — see the
  console output it prints either way).
- `packages/tampered-*.vep/` — copies of `valid.vep` with exactly one thing
  changed, each demonstrating one check in `peaceos-verify check` failing:

  | Package | What changed | Check that fails |
  |---|---|---|
  | `tampered-asset-altered.vep` | one byte flipped in the asset file | Integrity |
  | `tampered-signature-invalid.vep` | one byte flipped in `signatures/manifest.sig` | Field signature |
  | `tampered-key-mismatch.vep` | `keys/field-01.pub` swapped for a different (validly-formed) key | Field signature — this is the check that makes the field key non-substitutable; see `public_key_sha256` in `spec/CRYPTO_CONTRACT.md` |
  | `tampered-org-countersign-invalid.vep` | one byte flipped in `signatures/org-countersign.sig` | Org countersignature |
  | `tampered-path-traversal.vep` | `signature.sig_ref` rewritten to `"../../../../../../etc/passwd"` | Field signature, rejected as an unsafe path before any file is opened |

Try it:

```
peaceos-verify check examples/packages/valid.vep --transparency examples/transparency
peaceos-verify check examples/packages/tampered-key-mismatch.vep --transparency examples/transparency
```
